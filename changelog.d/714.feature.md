The `manageOrgData` capabilities `list` operation now provides a dependable machine-readable contract. `limit` remains 10 by default, accepts positive integers up to 10000, and rejects invalid values consistently through MCP and REST. Responses include `totalCount`, `returnedCount`, the effective `limit`, and an authoritative `truncated` flag. The new `identityOnly` projection returns only `id` and `resourceName`, while generated fixtures under `contracts/capabilities/` pin the published wire shape. Capability counts now use Qdrant's count API instead of fetching every stored payload.

The server also exposes authenticated `GET /readyz` for controllers and operators to determine whether Qdrant and embeddings can serve a new capability scan. The check is read-only, cached for 30 seconds, coalesces concurrent requests, and returns `503` within 10 seconds when a required dependency is unavailable. Collection existence and `storedCount` remain informational because a scan can initialize an absent collection. The chart intentionally keeps both Kubernetes probes on `/healthz` so a capability dependency outage does not remove the single API replica from service.
