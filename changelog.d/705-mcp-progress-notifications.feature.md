Long-running MCP tool calls (notably `recommend`) now emit `notifications/progress` for their whole duration, keeping the connection alive so a proxy/load-balancer idle timeout no longer drops an in-flight request. Progress is opt-in per call via `_meta.progressToken`; callers that do not send one — and all REST callers — are unaffected. A time-based heartbeat (default ~20s, configurable with `DOT_AI_MCP_PROGRESS_INTERVAL_MS`) guarantees liveness, and `recommend` layers semantic phase labels on top. To also extend the *client's* own request deadline, the client must set `resetTimeoutOnProgress` (bounded by `maxTotalTimeout`) when calling the tool.
